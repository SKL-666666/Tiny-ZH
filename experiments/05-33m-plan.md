## 为什么做这个

E2.3 的 64M 拿到 42/105（40.0%），minimind-3 是 74/105（70.5%）。

**差距 30 个百分点。归因：预训练数据质量，不是 token 数。**

本次目标：**用一半参数 + 正确的数据，追到 55-65%。**

---

## 架构（minimind-3 等比缩小）

```python
ModelConfig(
    vocab_size=6400, hidden_size=512, num_layers=9,
    num_heads=8, num_kv_heads=4, head_dim=64,
    intermediate_size=1664,      # FFN = 3.25×hidden
    max_position_embeddings=1024,
    rope_theta=1000000.0,
    tie_word_embeddings=True,
)
# 33,367,552 参数
```

### 比例保持

| 项 | minimind-3 | 本方案 | 倍数 |
|---|---|---|---|
| hidden | 768 | 512 | 0.67× |
| 层数 | 8 | 9 | 1.13×（补偿变窄） |
| num_heads | 8 | 8 | 1.00× |
| num_kv_heads | 4 | 4 | 1.00× |
| head_dim | 96 | 64 | 0.67× |
| **FFN/hidden** | **3.17** | **3.25** | **1.03×** ✅ |
| rope_theta | 1e6 | 1e6 | 相同 |

**设计原则：不发明新结构，只等比缩放。** 任何偏离都是赌博。

### 为什么不用 MobileLLM 的 30 层

33.37M 里词表占 9.8%（3.28M），剩下 30.1M 分给层。
- 9 层 → 每层 3.34M，FFN 3.25× ✅
- 30 层 → 每层 1.0M，FFN 1.0× ❌ 比例崩坏

**这是参数预算的硬约束。**

### 实测方法

每个源用 Range 请求只取 25-30MB，统计：
- 平均长度、p10/p50/p90/p99
- 中文占比（`[\u4e00-\u9fff]` 占比）
- 合格率（中文≥0.65 且 100-2000 字）

**不下载全文就下判断，避免浪费。**

## 训练配置

```bash
--seq-len 768              # minimind-3 推荐值
--micro-batch 32
--grad-accum 2             # 有效 49,152 tok/step
--lr 8e-4                  # 33.37M 比 64M 可用更高 lr
--max-steps 13,580         # 6.67亿 / 49,152
--warmup-ratio 0.03
```

**seq 768 的依据**：pretrain_t2t 的 p90=482 字 ≈ 720 token，768 刚好覆盖。

### 烟雾测试的判据

```bash
python3 train.py --mode pretrain --data bin --out out/smoke \
    --seq-len 768 --micro-batch 32 --grad-accum 2 --lr 8e-4 --max-steps 50
```

必须满足：
- loss 从 8.8 降到 7.5 以下
- 无 `nan` / `inf`
- 显存 < 20GB

**失败处理：改 `--dtype fp32`（慢 2 倍但稳定）。**

> 2026-11-15 | **已完结** | 最好成绩 42/105（40.0%）

参数从 31.5M 提到 64.8M，做了两次 SFT。对照组 minimind-3 是 70.5%。

## ⚠️ 这一轮的核心错误

**预训练数据配比错了。**

| 数据源 | 占比 | 问题 |
|---|---|---|
| **LCCC** | **55%** | **平均 46 字/段，碎片化** |
| FineWeb-Edu-v2 | 35% | 网页噪声 |
| **pretrain_t2t** | **0%** ❌ | **最好的数据完全没用** |

9.42 亿 token 里 5.2 亿是碎片，模型只学到局部词搭配，学不会长程连贯。

**对比 minimind-3（同样 64M）：它用 pretrain_t2t（274 字完整段落），只训 2.5 亿 token（4×），2 小时，拿到 70.5%。**

**我们 token 多 3.8 倍、时间长 2.7 倍，只有 40%。**

## v2 相比 v1 的改进

**SFT 数据从 ShareGPT 换成 minimind：**

| 项 | v1（ShareGPT） | v2（minimind） |
|---|---|---|
| 样本 | 5.7 万 | **11.3 万** |
| 答案长度 | 无限制（平均 1735 字） | **70-200 字** |
| 短问答 | 没有 | **2.5 万条（10-60 字）** |
| 编号列表 | 未过滤 | **剔除 9539 条** |
| 步数 | 1200 | 3375 |
| lr | 1e-4 | 8e-5 |
| val | 1.9357 | **1.7856** |

**效果：编号列表 2→0，中文不足 2→0，得分翻倍。**

## 教训

1. **数据质量比 token 数重要** —— 这是最贵的一课
2. **SFT 数据源决定格式**（编号列表、复读、模板回避）
3. **身份标签会污染自我认知**（「我是 minimind」）
4. **最好的数据不能排除**
